Compare the SHA-256 above with the build hashes published in the JRock repository (and optionally download the JAR to hash it yourself), then press Run JRock. Your Bedrock region and API key go into JRock's own Configure dialog, exactly as on the desktop: they are kept in this browser's storage, so they are still there after a reload.

A few seconds after JRock starts, this page's header and footer are hidden so the app gets the whole tab. To bring them back - to check the checksum, or to read the page's own log - click the __JRock/ label beside JRock's own Configure button and choose Show/hide the page header & footer.

Bookmark a folder and it runs by itself. Add a folder name to the address and JRock starts in it the moment the page loads, with no button to press - so one bookmark opens one project's own settings, key, prompt and log: ?home runs it in /files/home, and ?home/invoices in a folder under that. A folder that is new is created. The address is written out in full here so it can be copied or bookmarked as readily as clicked.

Files... opens what this browser has stored under /files - every folder JRock has written in, with a Delete beside each entry and one button that sweeps every name ending in ~ out of the whole tree. Only before JRock starts: nothing should be deleted under a running session.

Deleting a folder deletes everything in it. uploads/ and downloads/ are CheerpJ's own and are left alone.
Runs unmodified JRock Java bytecode via CheerpJ (WebAssembly + JS). Bedrock calls go out through this page's own HTTP fetch(), with the API key JRock holds: put it into JRock's Configure dialog. A short-term key can be generated in the AWS console. Use a Java window's title-bar upload button to load a local file into /files/uploads/; anything JRock saves under /files/downloads/ is downloaded to your machine.
